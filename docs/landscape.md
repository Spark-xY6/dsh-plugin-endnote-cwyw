# EndNote & Word Citation Workflows: Existing Tools and Design Choices

A collaborator sends a Word draft with live EndNote citations. You have an older EndNote library and a folder of PDFs. Two PDFs describe the same paper under slightly different titles. An old record number in the draft also points to a different paper in your library. The practical question is whether you can add the missing evidence and give the collaborator a Word file they can keep editing with EndNote.

EndNote already supplies the essential technology. Its Word add-in stores bibliographic data inside each formatted citation, the *Traveling Library*. That allows EndNote to format a document even when the original library is unavailable. Clarivate also documents that the same reference can have different record numbers across computers. A correctly rendered reference list is therefore insufficient to identify which record a subsequent edit will use. [Traveling Library](https://docs.endnote.com/docs/endnote/2025/v1/windows/en/content/09word/the_traveling_library.htm) · [Working on different computers](https://docs.endnote.com/docs/endnote/2025/windows/v1/content/09word/working_on_diffrntcomptrs.htm)

## Which existing tools fit which job?

The table covers the workflows described by their maintainers, checked on 2026-11-21. A companion study ran three of the EndNote utilities on the same draft, tested a dedicated deduplicator on two external datasets, and compared fresh agent sessions with and without these skills. ## What the integration adds

1. **Evidence for a placement.** The agent reads the candidate PDF pages, identifies the sentence in the manuscript, and records why the cited work supports it. A bibliographic match only establishes the identity of the article.
2. **One record per work in this document.** The workflow compares DOI, PubMed ID and bibliographic evidence against the target library before import. When equivalent records already exist, it prefers one already cited in the document. A small title variation without a usable identifier requires additional evidence. Similar records with conflicting identifiers are referred for review. Other manuscripts can continue using existing library records.
3. **A matched pair the collaborator can edit.** The workflow creates a copy of the library, reconciles the manuscript's embedded citations against it, and lets the installed Word add-in format the result. The final checks compare the saved citation locations, record identities and library binding before publishing the pair. A failed attempt leaves the input pair available for recovery.

Native Windows Word, a compatible installed EndNote desktop with CWYW, and access to the manuscript and its literature are required for the native route. A successful run on a chosen fixture answers whether that fixture can be updated. It does not measure citation selection accuracy across fields, deduplication recall on arbitrary libraries, or compatibility with every Word style, footnote and third-party citation system. ## Practices adopted from existing projects

| Design precedent | What you can inspect in this implementation |
| --- | --- |
| PubMate lets its users preview a conversion and inspect its report. [PubMate](https://github.com/jgassens/PubMate) | The read-only preview lists each selected PDF and each existing Word citation against the closed target library. It identifies records to reuse, new papers, and multiple inputs that would share a single new record. Journal identification conflicts leave the whole batch under review, with no asserted import total. [Preview implementation](../skills/cite-from-pdfs/scripts/preview_import.py) |
| JabRef shows differences between competing records. Zotero exposes mismatched fields when choosing a master item. [JabRef](https://github.com/JabRef/user-documentation/blob/main/en/finding-sorting-and-cleaning-entries/findduplicates.md) · [Zotero](https://www.zotero.org/support/duplicate_detection) | The private preview shows normalized identifiers, title, first author, year, journal, volume and first page for the incoming work and its candidates, and names the differing fields. It also exposes an embedded record number that now points to an unrelated target record. The source library is read through a temporary snapshot. [Preview tests](../tests/test_preview.py) |
| dsh-zotero lets readers check the source of an extracted passage and the annotated page. [dsh-zotero](https://github.com/Vncntvx/dsh-zotero/blob/main/docs/getting-started.en.md) | Each proposed placement carries a rationale, quotation and physical PDF page. The page check reopens that PDF and verifies the quoted text before import. Readers still need to decide whether the passage supports the claim. [Page check](../skills/cite-from-pdfs/scripts/placement_evidence.py) |

These public designs informed the workflow. The preview and page checks are implemented in this repository. The detailed preview is intended for the document owner because it contains bibliographic metadata from the local library.
