# Cite from PDFs

Given the PDF directory, old `.enl` with its paired `.Data`, and DOCX, complete the authorized citation update on copies. Provide the resulting Word and its matching updated library together. Existing genuine EndNote citations may be in the target library or in another EndNote library.

For a first-time user, take the three paths in ordinary language and build the plan yourself. When they ask for a preview, show the exact target sentence, one-based main-document paragraph number, physical PDF page and reuse/add decision. The private `--explain zh` or `--explain en` option prints these details for a local review. Ask the user to resolve only genuinely ambiguous matches. Use the default compact output for shared logs.

1. Use the Windows Python 3.10+ environment with this repository's dependencies installed. Run `python -X utf8 scripts/doctor.py` if Word/EndNote readiness is uncertain. Require a closed EndNote library before snapshots and imports. Never edit either EndNote database via SQLite or close pre-existing Office processes.
2. Run `scripts/index_pdf_folder.py index` using the supplied PDF directory/library and a new work directory. Index locally by default. Enable `--enrich-missing-metadata` only for a collection approved for online DOI, arXiv ID or title lookups. Search its catalog for the manuscript's uncited claims, then read the actual source pages. Use the full-text support and metadata to choose citations. Titles or search scores alone do not establish evidence. Use an approved model provider for any manuscript content read in the agent session.
3. Build the citation plan from the DOCX yourself. For each new citation record the exact anchor, PDF IDs, rationale and a short verbatim quotation on a one-based physical PDF page for every selected ID (use `"position": "auto"` by default so Nature citations sit after English periods with no leading space and before Chinese punctuation). Search indexes cover up to the first thirty pages (`--max-pages 30`). Inspect later pages directly when needed. Run the read-only `preview_import.py` command in the workflow guide before official import. Keep its report local. Resolve or omit uncertain placements and report them. If the user authorizes automatic completion, carry supported decisions through. If the user requests review first, return the preview.
4. Run the prepare, native format (always passing the explicit candidate `--enl`) and publish commands in [workflow and troubleshooting](references/workflow-and-troubleshooting.md). Execute the emitted formatter command directly from PowerShell as its own process. This creates a full candidate library, rematches identities, reconciles existing CWYW records, imports only missing works, formats via the official Word add-in and audits the saved outputs. It publishes the pair only after the audit passes.
5. Deliver `manuscript_cwyw.docx`, the paired `library/*.enl` and matching `.Data`, and `audit.json`. Report omitted placements and any document-specific verification limits. The user's source library stays available throughout recovery.

Refer to [workflow and troubleshooting](references/workflow-and-troubleshooting.md) for the plan, duplicate decisions and recovery. For particular existing field types and native Word verification, use [endnote-cwyw](../endnote-cwyw/SKILL.md).
